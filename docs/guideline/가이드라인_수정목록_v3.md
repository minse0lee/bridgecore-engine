## 0. 작업 원칙

- **범위**: 6축 정의는 그대로 둡니다. 판단 질문, 경계 규칙, 예시, 진행 방식, 평가폼을 보강합니다. 축 정의 자체를 바꿔야 하는 부분은 3절에 "결정 필요"(D1~D8)로 따로 모았습니다.
- **근거의 우선순위**
  1. 세 평가자의 판정이 실제로 갈린 칸 (R001 수정본 기준, P001 Semantic은 유정님 확인대로 훼손·minor)
  2. 민서 검토 의견 + 수안님 일치도 분석 7절
  3. 지침·문맥 의견 (70건 중 69건이 R003, 1건이 R001, R002는 0건) → 왜 헷갈렸는지를 보여주는 보조 자료. 한 사람의 의견이라 그대로 일반화하지 않습니다.
  4. **설계자 의도 훼손 목록** (수안님, 28문항 55칸) → 설계 의도를 보여주는 보조 자료. **정답이 아닙니다.**
     - 55칸 중 사람 다수결(2명 이상)이 훼손인 칸은 26칸, 아무도 훼손으로 보지 않은 칸이 10칸
     - 55칸 중 34칸은 LLM이 찾은 오류(LLM분석)라 LLM 쪽 판단이 섞여 있음
     - 의도와 사람 판정이 다르면 자동으로 의도를 따르지 않고 **D7**에서 설계자 검토로 확정
- **예시 문항 주의 (중요)**: 엔진 프롬프트가 가이드라인을 그대로 따르므로, 가이드라인 예시에 **파일럿 확인용(holdout) 20문항**을 쓰면 엔진이 그 정답을 미리 보게 됩니다. 예시는 **합성 예문** 또는 **개발용(dev) 문항**만 씁니다. → 5절

## 3. 결정이 필요한 쟁점

축 정의를 바꾸지는 않지만 **적용 범위가 달라져서 정답에 영향을 주는** 항목입니다. 추천안을 붙였지만 수안님 확인이 필요합니다. 리서치 문서가 오면 5절 경계 규칙과 대조합니다.

**D1. Semantic: 경미한 어감·강조 변화**
- 쟁점: overbearing→"압도적인"(P037), critical→"중요한"(P058) 같은 정도·어감 차이를 훼손으로 볼지
- 추천: 2절 목록 항목 중 하나가 달라졌다고 특정할 수 있으면 훼손(minor), 평가어의 정도·어감 차이뿐이면 보존. 단 **확실성**(추측→단정, 기대→예측: P041, P049)은 목록에 있으므로 훼손

**D2. Deontic: 적용 범위**
| 유형 | 예 | 추천 |
|---|---|---|
| 자격·요건 진술 | Membership is required(P033), qualify as(P032) | **적용** (자격 조건) |
| 수령·지급 권리 진술 | Each student awarded … receives(P056) | **적용** (권리를 받는 주체·조건) — 논쟁 여지 큼 |
| 독자 대상 조언 | Let your child take a break(P015) | **적용** (규범적 권고). 단 원문이 선택 방법 안내면 "~할 수 있다"도 보존 |
| "It is critical that ~" 권고 | P058 | **적용** (강도 차이는 범주 변화가 아니면 보존) |
| 앞 문장 규범의 계승 | This includes …(P025) | **평가대상 문장 자체에 규범 표현이 없으면 N/A** ⚠️ 파일럿 다수결(보존 2명)과 반대 |
| 규정을 설명하는 계산 예시 | P054 | **N/A** (예시 서술). 제외 조건 등 규정 자체를 진술하면 적용 |
| 문학 속 자기 금지·의무 | I must not cry(P053) | **적용** (장르와 무관하게 규범 의미가 있음) |
| 대화 속 제안·선택 질문 | Or shall I?(P022) | **N/A** |
| 이용 방법 안내 | Use your PIN to access …(P005) | **N/A**, 지시 기능은 Context에서 판정 |
| 학습 활동 지시 | Use local resources to view …(P050) | **N/A** (기존 원칙 유지), Context에서 판정 ⚠️ **의도 목록은 P050 Deontic 훼손**(LLM분석). 사람은 N/A 2 · 훼손 1 |

- **의도 목록과 대조**: 자격 조건(P032), 수령 권리(P056), 문학 속 자기 금지(P053)는 의도 목록에도 Deontic 훼손으로 있어 추천안(적용)과 같은 방향. P015(독자 대상 조언)도 Deontic 의도 칸이지만 확인용 문항이라 예시로 쓰지 않음. **어긋나는 건 P050 하나** → 기존 원칙("학습 활동 지시는 Deontic N/A")을 유지할지, 학습 지시도 Deontic 대상으로 넓힐지 결정 필요. 추천은 기존 원칙 유지(사람 다수 N/A, 가이드라인 원문과 일치)
- 의도 목록의 P039 Deontic(학습자료 속 응급 처치)과 P045 Deontic(사람 0표)도 유형표에 없는 사례 → D7에서 확인

- 지수민 리서치 보강(표 3): 권고는 "**규범적 근거가 있는 행동 지침**"으로 범위를 정하고, 발신자의 단순 취향이나 사건 발생 예상과 구별 → 안내문 속 독자 대상 조언(P015)·권고(P058)는 적용, 대화 속 개인적 부탁·바람은 N/A
- 지수민 리서치 표 3의 **조동사별 한국어 대응표**(must→해야 한다 / may 허가→해도 된다 / must not→해서는 안 된다 vs 할 필요 없다 / need not / should 권고 vs 예상)를 5절에 넣기. 단 "고정 번역표가 아니라 문맥 확인 후 적용하는 예시"라는 단서 포함

**D6. Context가 의무와 권고의 차이까지 보는가** (지수민 리서치 4-2에서 제기)
- 쟁점: "Students must wear eye protection." → "착용하는 것이 좋다"처럼 의무가 권고로 바뀌었을 때 Context도 훼손인가
- 추천: **Context는 발화 기능의 범주(지시·요청·질문·설명·경고 등)가 바뀌었는지만 보고, 의무·권고의 강도와 범주는 Deontic에서** 봄 → 위 예는 Deontic 훼손(+Semantic 공동 가능), Context 보존. 지시가 가능성 **설명**으로 바뀐 경우(2절 표 10번, P050 유형)는 기능 범주가 바뀐 것이므로 Context 훼손 유지
- 근거: 리서치 표 6 "Context를 발화 기능 중심으로 한정"
- ⚠️ **의도 목록과 충돌**: P053(must not → "않아도 됩니다")은 의도 목록에서 **Context도 훼손**. D6 추천안대로면 이건 Deontic(+Semantic) 훼손, Context 보존. 사람 3명도 Context는 모두 보존, 엔진 v0는 세 방식 모두 Context 훼손 (엔진의 Context 과잉 표시와 같은 유형)
  - D6를 채택하면 P053 Context는 "의도는 훼손이었지만 기준상 보존"으로 정리
  - 채택하지 않으면 "금지가 비의무로 바뀌면 발화 기능(금지→허용)도 바뀐 것"이 되어 Context 범위가 넓어짐 → 엔진 과잉 표시가 오히려 정답이 됨

**D3. Cultural: 고유명사만 있는 문장**
- 쟁점: 인명·지명만 있는 문장(P016 Easter Island, P021 Sherman·Richmond, P047 Sport)을 N/A로 볼지 보존으로 볼지 (평가자마다 다름)
- 추천: 인명·지명은 그것만으로 Cultural 대상이 아님 → **N/A**. 단 제도·기관명·법령명·약어(P012 FERPA)는 대상 → 보존/훼손 판정
- ⚠️ 이대로 가면 P016·P021은 파일럿 다수결(보존 2명)과 반대가 됨

> **참고**: 추천안이 파일럿 다수결과 달라지는 칸(P025 Deontic, P016·P021 Cultural)은 엔진 개발용 임시 정답에서 "구 기준"으로 표시해 두는 게 좋습니다. 셋 다 훼손 여부(이진 정답)에는 영향이 없고 4범주 보조 지표에만 영향이 있습니다.
